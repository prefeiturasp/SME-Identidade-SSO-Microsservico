class apps.cache.services.CacheService[código-fonte]

Base: object

Serviço responsável pelas operações de cache.

O KeyDB é a única fonte de verdade da sessão compartilhada — não há fallback a um banco relacional, diferente do uso de cache do SME-Identidade-Token-Microsservico. Por isso, além das operações usuais (fail-safe, nunca propagam exceção), este serviço também expõe disponivel(), usado para distinguir “sessão não existe” de “cache indisponível” quando obter() retorna None.

apps.sessoes.logout_global.notificar_logout_global(sessao)[código-fonte]

Notifica os sistemas conectados à sessão sobre o logout global.

Dispara uma notificação em paralelo para cada sistema com callback configurado (settings.LOGOUT_CALLBACKS). Sistemas sem callback registrado são marcados como falha sem tentativa de rede — não há ainda um cadastro de sistemas com metadados de URL, então essa configuração estática é uma lacuna conhecida, não um erro de execução.

Cada notificação é enviada com a mesma API Key usada para consultar o Gateway (settings.API_KEY_GATEWAY_MS) — reaproveita a credencial já configurada em vez de introduzir uma chave dedicada por sistema de callback, já que hoje o único receptor real é o endpoint de teste E2E do próprio Gateway.

Esta função nunca propaga exceção: cada falha (timeout, erro de transporte, status não-2xx, ausência de callback) é isolada por sistema e reportada no resultado, sem interromper a notificação dos demais.

Parâmetros:

sessao – Sessão encerrada, com a lista de sistemas conectados.

Retorna:

Um resultado por sistema da sessão, na mesma ordem.

Parâmetros:

sessao (Sessao)

Tipo de retorno:

list[ResultadoNotificacao]

static autenticar_e_criar_sessao(login, senha)[código-fonte]

Autentica no Gateway e cria a sessão compartilhada.

A autenticação real acontece no Keycloak, via Gateway. Se ela for bem-sucedida mas a criação da sessão falhar por indisponibilidade do Gateway (segunda chamada, para obter os sistemas do usuário), o login não é desfeito — a sessão apenas fica ausente na resposta.

Parâmetros:

  • login – RF, CPF ou username do usuário.

  • senha – Senha em texto plano.

Retorna:

Dados de autenticação e a sessão criada (ou o motivo da falha, se a sessão não pôde ser criada).

Levanta:

  • LoginError – Login ou senha inválidos.

  • GatewayIndisponivelError – O Gateway não respondeu a tempo ou está inacessível na chamada de autenticação.

Parâmetros:

  • login (str)

  • senha (str)

Tipo de retorno:

ResultadoLogin
